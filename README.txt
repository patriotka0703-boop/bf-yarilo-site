БФ «ЯРИЛО» — документы фонда
Версия 20260919.1

ГОТОВО
В админке добавлен раздел «Документы фонда»: Устав фонда, Политика конфиденциальности, Публичная оферта.
Можно загрузить PDF или сканы JPG/JPEG/PNG/WEBP: до 8 МБ на файл, до 20 файлов в каждом разделе, в том числе несколько сразу. У каждого файла можно изменить название, открыть его и удалить. Публикация и удаление происходят после кнопки «Сохранить изменения».
Посетители смогут открыть и скачать документы. Все три раздела доступны на странице «Отчётность», а ссылки на устав, политику и оферту — внизу страниц сайта.
Сами утверждённые документы нужно загрузить через админку: тестовых файлов и придуманного текста оферты в обновлении нет.

УСТАНОВКА — ОДИН РАЗ
1. Распакуйте этот ZIP. Откройте cloudflare/yarilo-admin-auth.js в Блокноте, скопируйте его целиком. В Cloudflare откройте существующий Worker yarilo-admin-auth → Edit code. Замените весь код worker.js скопированным кодом и нажмите Deploy. Отдельные строки изменять не нужно; настройки и секреты Worker оставьте прежними.
   Проверка: https://yarilo-admin-auth.patriotka0703.workers.dev/health должен показать:
   {"ok":true,"version":2,"features":{"documents":true}}
2. В GitHub откройте patriotka0703-boop/bf-yarilo-site, ветка main → Add file → Upload files. Из распакованной папки перетащите папку admin и все файлы сайта, лежащие рядом с ней. Папку cloudflare, README и сам ZIP на GitHub не загружайте. Нажмите Commit changes.
   В списке загрузки пути должны выглядеть как admin/admin.js, admin/index.html, reports.html, offer.html. Перед ними не должно быть YARILO-DOCUMENTS или site. Существующие файлы репозитория заранее удалять не нужно.
3. Дождитесь успешной публикации в GitHub → Actions. Откройте https://bf-yarilo.ru/admin/ и нажмите Ctrl+F5. Войдите через GitHub → «Документы фонда» → выберите файлы в нужных разделах → «Сохранить изменения».

ДАННЫЕ СОХРАНЯЮТСЯ
Это обновление существующего сайта. В архиве нет site-data.js, пользовательских фотографий, видео, настроек входа и домена: действующие данные не заменяются старой копией. Сохранены предыдущие обновления соцсетей, описаний фотографий, реквизитов и места для QR-кода.
Для документов обязательно нужен Worker из этого архива. Если сервер ещё не обновлён, админка выдаёт понятное сообщение и не сообщает о ложном сохранении файлов.

ЧТО РЕАЛЬНО ПРОВЕРЕНО
38 автоматических проверок с обновлённым Worker: вход OAuth на имитации GitHub, загрузка медиа и PDF, проверка форматов и размеров, все три категории документов, сохранение нескольких файлов, переименование, замена, удаление отдельного файла, защита от устаревшего сохранения и сохранность остальных данных.
Проверен синтаксис JavaScript и встроенных скриптов/JSON-LD; проверены 16 HTML-страниц и 459 локальных ссылок.
На локальном сервере в браузере проверены: одновременная загрузка PDF и скана, загрузка во все три раздела, сохранение и перезагрузка админки, переименование и удаление отдельного скана, отображение на страницах отчётности, политики и оферты, скачивание PDF и переход к нему в новую вкладку, восстановление прежнего текста политики при удалении загруженной политики. Проверено сообщение при старом Worker. Страница документов проверена при ширине 390 px без горизонтального переполнения.
Проверки сервера выполнялись с имитацией GitHub и тестовыми файлами; тестовые документы на действующий сайт не публиковались. Реальный вход и публикация новой версии на рабочих сервисах в этот комплект проверок не входят. Встроенный просмотр PDF в браузере не подтвердился снимком экрана; скачивание и открытие вкладки с адресом PDF подтверждены.
ZIP проверен на целостность, а файлы внутри сравнены с проверенными исходниками.
